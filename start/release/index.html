출시도 Claude에게 말로 해요. 빌드와 업로드는 클라우드에서 해서 PC에 아무것도 깔지 않아도 돼요. 플랫폼마다 하는 말과, 그 말을 하면 일어나는 일을 모았어요.

모든 빌드

빌드는 늘 이 순서예요

  1. 말하면 Claude가 지난 빌드 이후 바뀐 점을 정리해 보여 줘요. 처음이면 지금까지 만든 내용을 보여 줘요.
  2. 버전을 물어요. 추천 버전과 이유를 보여 주고, 원하는 번호를 말해도 돼요. 답하기 전에는 빌드하지 않아요.
  3. 답하면 클라우드에서 빌드하고, 빌드한 커밋에 버전 이름표(태그)를 달아요. 나중에 어느 버전이 어떤 코드였는지 찾을 수 있어요.

커밋 메시지가 '추가: …', '수정: …'으로 시작하면 바뀐 점 정리와 버전 추천이 더 정확해져요. Claude Code는 공통 지침대로 이렇게 써요.

웹 공개

플레이할 수 있는 화면이 생기면요. 웹으로 만든 게임만 돼요.

이 사이트의 프로젝트 주소 아래 play/에 게임을 올려요. 링크를 받은 사람은 휴대폰 브라우저에서 바로 해 볼 수 있고, 프로젝트 소개 페이지에 '플레이해 보기' 버튼이 생겨요.

  • pushpath 테스트 링크 만들어 줘

    바뀐 점과 추천 버전을 보여 주고 버전을 물어요. 처음이면 0.1.0을 추천해요. 답하면 1~3분 뒤 플레이 주소를 알려 줘요.

  • 테스트 기능은 끄고 올려 줘

    치트·디버그 메뉴 같은 테스트 기능을 빼고 올려요. 말하지 않으면 테스트 기능을 켜고 올려요.

누구나 열 수 있는 주소예요. 아직 보여 주면 안 되는 내용은 올리지 않아요.

올린 뒤 1~2분은 예전 화면이 보일 수 있어요. 화면이 하얗게 나오면 Claude가 알려 준 오류를 Claude Code에 붙여 "이거 고쳐 줘"라고 해요.

바로 써요

구글플레이

테스트해 보고 앱으로 내보낼 때요. 웹 게임은 같은 빌드를 안드로이드 앱으로 감싸고, Unity 게임은 Unity로 빌드해요.

테스트 빌드 → 내부 테스트
따로 말하지 않으면 이걸로 만들어요. 테스트 기능을 켤 수 있고, 광고는 늘 구글 테스트 광고예요. 정식 출시로는 못 가요.
배포용 빌드 → 비공개 테스트
테스트 기능을 모두 끄고 진짜 광고를 넣어, 정식 출시 기준으로 진단한 뒤 올려요. 정식 출시(프로덕션)는 이 빌드만 갈 수 있어요.

  • pushpath 출시하고 싶어

    처음이면 마켓부터 물어요. 테스트 기능·광고·인앱 상품을 켤지 고르고, 막히는 곳이 있는지 진단한 뒤 버전·출시 노트·테스터를 확인해서 테스트 빌드를 만들어요. 처음 올리는 앱은 1.0.0을 추천해요.

  • Play Console 다 했어

    첫 출시 때만 써요. 콘솔에서 앱을 만들고 첫 파일을 올린 뒤 말하면, 스토어 문구·그래픽·데이터 보안을 올리고 테스터를 연결해요.

  • pushpath 업데이트 올리자

    바뀐 점과 버전, 출시 노트를 확인하고 테스트 빌드를 내부 테스트에 올려요. 테스트 참여 링크도 알려 줘요.

  • pushpath 배포용 빌드 만들어 줘

    테스트 기능을 모두 끄고 진짜 광고를 넣어 비공개 테스트에 올려요. "정식 출시하자", "출시용으로 해 줘"라고 해도 돼요. 광고를 쓰면 관리자가 광고 키를 승인한 뒤에 만들 수 있어요.

  • 빌드 어때?

    빌드가 끝났는지 보고, 끝났으면 이어서 올려요.

  • 테스터에 friend@gmail.com 넣어 줘

    내부 테스트 테스터로 넣어요. 테스트 폰의 플레이 스토어 계정이 Claude에 로그인한 계정과 다를 때 써요.

  • pushpath 프로덕션에 10%로 올려 줘

    관리자만 해요. 비공개 테스트에 올린 배포용 빌드를 정식 출시해요. 비율만 바꿔 다시 말하면 조금씩 늘어나요. 관리자가 아니면 관리자에게 부탁해요.

  • pushpath 출시 상태 알려 줘

    트랙마다 올라간 버전과 상태를 알려 줘요.

처음 출시할 때 한 번 더 할 일

  1. 스토어 아이콘(512x512 PNG), 그래픽 이미지(1024x500), 스크린샷 2~8장을 드라이브 프로젝트 폴더의 '스토어 이미지'에 넣어요. 그 아이콘이 앱 아이콘도 돼요.
  2. 스토어 문구와 앱 콘텐츠 답변(콘텐츠 등급 설문 포함)은 Claude가 초안을 써서 보여 줘요. 고칠 곳만 말하면 저장해요.
  3. 빌드가 끝나면 Claude가 Play Console 입력표와 서명된 앱 파일 링크를 줘요. 입력표대로 Play Console에서 앱을 만들고 첫 파일을 올려요.
  4. "Play Console 다 했어"라고 말하면 나머지는 Claude가 올려요.

정식 출시는 배포용 빌드로만 해요. 테스트 빌드는 내부 테스트까지만 가요.

광고를 켜면 광고 키는 관리자 승인을 거쳐 만들어져요. 승인 상태는 빌드 전 보고에 같이 나와요.

등급분류 자료만

토스 (앱인토스)

앱인토스에 처음 낼 때요. 토스에 빌드를 올리는 일은 아직 준비 중이에요.

토스에 게임을 처음 내면 앱인토스 콘솔의 '게임 등급분류' 화면을 채워야 해요. Claude가 그 화면의 칸 순서대로 입력표(구글 시트)를 드라이브에 만들어 링크로 줘요.

  • pushpath 토스 첫 출시 준비해 줘

    입력표, 프로젝트 자료 폴더, 회사 공통 자료 링크를 주고 남은 할 일을 알려 줘요.

  • 토스 등급분류 자료 다시 확인해 줘

    입력표에 적은 값과 넣은 화면을 보고 남은 것만 알려 줘요. 적은 값은 지워지지 않아요.

등급분류는 이 순서로

  1. 구글플레이 첫 출시부터 해요. Play Console에서 콘텐츠 등급 설문을 내면 게임물관리위원회에 자체등급분류 결과가 생겨요.
  2. 게임물관리위원회 자체등급분류 게임물 조회에서 게임 이름으로 찾아 등급분류일자·번호·이용등급·내용정보를 입력표에 적어요.
  3. 내용정보가 있으면 항목마다 같은 장면을 두 장 찍어 자료 폴더에 넣어요. 구글플레이 버전 화면과 토스 앱 화면이에요.
  4. 앱인토스 콘솔에서 앱 등록하기 → 게임 등급분류에 입력표 순서대로 넣어요.

회사 정보(등록 정보, 대표자 인감·사인, 증빙자료)는 관리자가 한 번 준비해 둬서 모든 게임이 같이 써요. 전체 이용가면 내용정보와 화면은 없어요.

더 자세한 건 앱인토스 안내 자체등급분류 게임물 정보 입력하기를 봐요.

막힐 때

출시하다 막히면

버전은 뭘로 해요?

Claude가 지난 빌드 이후 바뀐 점을 보고 추천해요. 새 기능이 있으면 가운데 숫자를, 고친 것만 있으면 끝자리를 올려요. 웹 공개는 0.1.0부터, 구글플레이 첫 출시는 1.0.0부터 시작해요.

빌드가 실패했어요

Claude가 이유와 해결 방법을 알려 줘요. 코드 문제면 그 내용을 Claude Code에 붙여 "이거 고쳐 줘"라고 하고, 고친 뒤 다시 빌드해요. 실패한 빌드의 버전은 다시 써도 돼요.

테스트 폰에서 내부 테스트 앱이 안 보여요

테스트 폰의 플레이 스토어 계정이 테스터로 들어가 있어야 해요. "테스터에 (그 계정) 넣어 줘"라고 한 뒤, Claude가 준 테스트 참여 링크를 그 폰에서 열어 참여해요.

광고가 테스트 광고로 나와요

테스트 빌드에는 늘 구글 테스트 광고가 나와요 (웹 공개에서는 '광고 자리' 화면만 보여요). 진짜 광고는 관리자가 광고 키를 승인한 뒤 만든 배포용 빌드에 들어가요.

Unity로 만든 게임도 되나요?

구글플레이 출시는 돼요. Unity로 빌드해요. 웹 공개는 웹으로 만든 게임만 돼요.
