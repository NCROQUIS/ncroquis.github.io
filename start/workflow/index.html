대화로 개발하고,
출시·업데이트·검증해요

하고 싶은 일을 대화창에 말하면 킥오프가 준비·점검·빌드를 진행해요. 아래 문장의 ‘〈게임명〉’을 내 게임 이름으로 바꿔 말해요. 코드를 만들거나 고칠 때는 그 게임 프로젝트가 열린 Claude Code·Codex 대화창을 써요.

처음에는 Claude 연결 또는 Codex 연결을 마쳐요. 버전 번호는 예시이며, 실제 변경 내용과 제안을 보고 골라요.

  1. 1장 · 개발 시작
  2. 2장 · 첫 출시
  3. 3장 · 업데이트
  4. 4장 · 프로젝트 검증 사이클

각 장은 1부터 6까지 화살표 순서로 읽어요. 도식은 같은 배치를 유지하며 작은 화면에서는 도식 안을 좌우로 이동해요. ‘문장 복사’는 요청 문장만 복사해요.

1장 · 개발 시작

아이디어를 말하고, 직접 플레이할 링크를 받아요.

1 · 킥오프가 연결된 AI 대화

만들 게임을 말해요

새 퍼즐 게임을 만들고 싶어. 킥오프해 줘.

AI가 처리해요기획을 정리하고 이름·코드네임 후보를 보여 줘요.

2 · 같은 대화에서 답하기

프로젝트 생성을 승인해요

이 기획과 코드네임으로 프로젝트 만들어 줘.

받는 결과게임 저장소·기획 문서·드라이브 폴더와 개발 링크가 생겨요.

3 · 받은 개발 링크로 게임 프로젝트 열기

플레이할 첫 버전을 만들어요

기획서를 읽고 플레이 가능한 첫 버전을 만들어 줘.

AI가 처리해요해당 게임의 코드를 작성하고 시험해요. Codex에서는 생성된 게임 저장소를 열고 요청해요.

4 · 같은 게임의 개발 대화

테스트 링크를 요청해요

〈게임명〉 테스트 링크 만들어 줘.

AI가 물어요지난번 이후 바뀐 점과 버전 제안을 보여 줘요.

5 · 제안 내용을 읽고 답하기

빌드 버전을 골라요

0.1.0으로 진행해 줘.

받는 결과AI가 빌드를 시작하고, 완료되면 브라우저에서 여는 플레이 링크를 알려 줘요.

6 · 링크를 직접 열어 플레이하기

문제를 같은 대화에 말해요

시작 버튼이 잘 안 눌려. 원인을 확인해서 고쳐 줘.

문제가 있을 때의 예시예요수정·테스트를 반복해요. 플레이가 잘 되고 출시할 준비가 되면 2장으로 가요.

반복하는 구간: 3 개발 요청 → 4 테스트 요청 → 5 버전 선택 → 6 직접 플레이. 기획이나 기능을 바꿀 때도 같은 게임의 개발 대화에서 이어서 말해요.

2장 · 첫 출시

플랫폼을 말하고, 자료와 실제 동작을 확인해요.

1 · 게임의 대화창에서 플랫폼 지정

첫 출시 준비를 요청해요

〈게임명〉 구글플레이 첫 출시 준비해 줘.

AI가 처리해요준비된 것과 빠진 것을 확인해요. 토스·App Store·웹·카카오는 플랫폼 이름을 바꿔 말해요.

2 · AI가 제시한 자료·질문 읽기

내용을 확인하고 답해요

앱 소개와 이미지, 광고·상품 설정, 개인정보 신고 내용을 함께 확인하자.

내가 확인해요타깃 연령·회원 연동·심사 연락처 등 필요한 답을 전달해요. 빠진 자료는 AI에게 보완을 요청해요.

3 · 스토어에 처음 내는 앱만

마켓 등록을 요청해요

첫 마켓 등록을 관리자에게 요청해 줘. 처리 상태도 알려 줘.

관리자 확인 구간관리자가 첫 등록을 처리해요. 등록 완료 후 다음으로 가요. 웹 공개·카카오 ZIP은 이 단계를 건너뛰어요.

4 · 버전을 정해 같은 대화에 요청

배포용 빌드를 만들어요

〈게임명〉 1.0.0 배포용으로 빌드해 줘. 테스트 확인 전에는 공개하지 마.

AI가 처리해요플랫폼 기준으로 점검·빌드해요. 테스트할 경로를 안내하고, 필요한 서명·업로드는 관리자 처리로 이어져요.

5 · 설치 링크로 실제 기기 확인

직접 실행하고 결과를 말해요

테스트할 설치 링크와 확인할 항목을 알려 줘.

내가 확인해요플레이·저장·광고·구매·복원을 확인해요. App Store는 실제 아이폰, 카카오 실기기 QA는 퍼블리셔와 진행해요.

6 · 확인한 결과를 대화로 전달

심사·공개 진행을 요청해요

테스트 끝났어. 필요한 심사·출시 절차를 진행해 줘. 공개되면 상태도 확인해 줘.

첫 출시의 관리자 처리스토어는 관리자 확인과 심사를 거쳐 공개돼요. 웹과 카카오는 아래의 최종 행동으로 이어져요.

구글플레이·토스
첫 등록·첫 공개는 관리자와 진행해요. 토스 게임은 구글플레이 출시·GRAC 등급 조회 준비가 먼저예요.
App Store
첫 Apple 연결·등록·출시는 관리자가 처리해요. 공개된 앱의 업데이트는 프로젝트 개발자가 TestFlight·심사·공개까지 진행하고 실제 아이폰 테스트를 마쳐요.
웹 공개
“〈게임명〉 웹에 공개해 줘.” → 발급된 플레이 주소를 직접 확인해요. 스토어 등록·심사는 없어요.
카카오페이·카카오톡
회원·저장·탈퇴 연동과 배너·인앱 끔을 확인해요. “〈게임명〉 카카오페이 전달용 ZIP 만들어 줘.” → 퍼블리셔에게 전달해요. 등록·배포·출시는 퍼블리셔가 맡아요.

대화로 요청해도 실제 테스트와 관리자 확인이 필요한 단계는 기다려요. Steam 파이프라인은 현재 구현 전이에요.

3장 · 업데이트

같은 게임을 고치고, 같은 앱의 새 버전으로 내요.

1 · 기존 게임 프로젝트의 개발 대화

바꿀 내용을 말해요

상점 버튼 오류를 고치고 초반 난이도를 낮춰 줘.

AI가 처리해요기존 코드와 설정을 이어서 수정하고 시험해요. 새 프로젝트를 만들지 않아요.

2 · 같은 대화에서 미리 보기 요청

수정한 게임을 플레이해요

〈게임명〉 수정한 내용으로 테스트 링크 만들어 줘.

내가 확인해요제안된 버전을 고르고 플레이 링크에서 수정 결과를 봐요. 문제가 있으면 1로 돌아가요.

3 · 새 배포 버전을 정해 요청

배포용 업데이트를 올려요

〈게임명〉 1.0.1로 구글플레이 배포용 업데이트 올려 줘. 공개는 테스트 확인 후 진행할게.

AI가 처리해요같은 앱의 새 버전을 빌드·업로드해요. 토스·App Store 등은 플랫폼 이름을 바꿔요.

4 · 새 배포용 빌드의 실제 기기 테스트

바뀐 점과 기존 기능을 봐요

이번 배포용 빌드의 테스트 경로와 확인할 항목을 알려 줘.

내가 확인해요수정 사항·기존 저장·광고·구매가 동작하는지 봐요. 토스는 QR, App Store는 아이폰 TestFlight로 확인해요.

5 · 검수가 끝난 뒤 같은 대화에 요청

새 버전 공개를 진행해요

새 버전 테스트 끝났어. 업데이트 공개 진행해 줘.

프로젝트 개발자가 진행해요출시를 마친 구글·토스·App Store 앱은 프로젝트 개발자가 업데이트 심사·공개까지 진행할 수 있어요. Apple 키와 인증서는 서버가 보관해요.

6 · 같은 대화에서 결과 확인

현재 공개 버전을 확인해요

〈게임명〉 지금 출시된 버전과 업데이트 상태 알려 줘.

받는 결과심사·공개 상태를 확인해요. 다음 개선도 같은 게임의 대화에서 1부터 이어서 요청해요.

웹·카카오의 마지막 행동: 웹은 같은 플레이 주소에 업데이트해요. 카카오는 새 버전 ZIP 다운로드 링크를 퍼블리셔에게 전달하고 QA·출시 결과를 회신받아요.

4장 · 프로젝트 검증 사이클

출시한 게임에 신규 이용자를 모으고, 지표로 다음 행동을 정해요.

현재 사이클 검증 대상은 출시를 마친 구글플레이·토스예요. 대화에서는 준비·결과 해석·개선을 요청하고, 사이클 생성·집계 시작·판정 기록은 검증 화면에서 해요.

1 · 출시를 마친 게임의 개발 대화

검증할 가설을 정해요

〈게임명〉 구글플레이 출시 버전으로 검증 사이클을 준비해 줘. 확인할 가설과 지표를 정리해 줘.

AI가 정리해요플랫폼·출시 버전과 검증할 가설 1~3개를 정해요. 토스는 플랫폼 이름을 바꿔 말해요.

2 · 같은 대화에서 관측 준비 확인

실제로 측정되는지 봐요

〈게임명〉 초기 5일의 약 100개 관측 지점과 판·광고·구매 지표가 출시 빌드에서 수집되는지 확인해 줘.

AI와 확인해요진행 단계·반복 동선·기존 이벤트를 점검해요. 빠진 기록은 고쳐서 3장 순서로 출시한 뒤 검증해요.

3 · 대화로 준비한 뒤 검증 화면 열기

사이클을 만들고 설정해요

〈게임명〉 사이클의 목표 신규 수·예산·기간과 준비 체크리스트를 정리해 줘.

내가 진행해요대시보드 ‘지표 → 사이클 검증 열기’에서 프로젝트·플랫폼을 골라 사이클을 만들고 설정을 확인해요.

4 · 모객 준비 후 관리자 확인

모객·집계 시작을 승인받아요

〈게임명〉 모객 계획과 예산·기간을 확인할 관리자 승인 요청문을 정리해 줘.

관리자가 처리해요광고 캠페인·토스 프로모션을 준비하고 ‘사이클 집계 시작’을 승인해요. 그때부터 신규·모객 비용을 세요.

5 · 측정 후 결과를 대화에 붙여 넣기

어디서 이탈했는지 봐요

〈게임명〉 이 사이클 결과의 D1·D3·D7, 이탈 지점과 모객 비용을 보고 개선 가설 1~3개를 정리해 줘.

내가 확인해요목표·예산·기간 중 먼저 닿으면 모객을 마치고 마지막 신규의 D7까지 측정해요. 결과를 대화에 함께 보내고, 표본이 적으면 판단을 미뤄요.

6 · 검증 화면에 판정·이유 기록

판정하고 다음 행동을 정해요

〈게임명〉 이번 결과에 맞춰 확장·개선·방치·중단을 선택할 근거와 다음 작업을 정리해 줘.

내가 결정해요화면에 선택과 이유를 남겨요. 확장은 관리자가 결정해요. 개선이면 3장으로 업데이트하고 출시 완료 후 새 사이클을 만들어요.

확장
관리자가 예산을 늘려 본격적으로 모객해요.
개선
가설 1~3개를 고쳐 출시하고 다음 사이클에서 비교해요.
방치
모객을 멈추고 스토어의 게임은 그대로 둬요.
중단
모객과 업데이트를 멈춰요.

검증 중 버전을 바꿀 때: 난이도·보상·튜토리얼 변경은 판정 뒤에 내거나 사이클을 취소하고 새 버전으로 시작해요. 긴급 오류 수정은 출시 후 검증 화면의 ‘핫픽스로 이어가기’에 이유를 남겨요.

연결부터 다시 보려면 시작하기, 플랫폼별 자세한 요청 문장은 출시하기를 봐요.
